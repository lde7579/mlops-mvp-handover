# E2E 데모 시나리오 (= 테스트 케이스)

> 기준: `mlops-mvp-project-brief.md` 10장. 이 8단계가 **화면에서 끝까지 한 번에 동작하면 프로젝트 성공**입니다.
> 구현 중에는 각 단계를 자동 테스트(`tests/e2e/`)로도 옮깁니다.

---

## 0. 사전 준비 (시연 전 한 번만 수행, 화면 밖 작업)

| 항목 | 내용 | 확인 방법 |
|---|---|---|
| 고정 테스트셋 생성 | test_normal 500건 + test_drift 500건 (불량 약 20%) | DB에서 data_split별 건수 확인 |
| v1 학습 | train 데이터(normal만)로 v1 학습, test_normal 평가 | `models/v1/model.pt`, `metrics.json` 존재 |
| v1 production 등록 | v1을 production으로 등록 | 대시보드 운영 모델 = v1 |
| 계정 | operator, admin 고정 계정 | 로그인 가능 |
| 초기화 스크립트 | 시연 반복을 위해 데모 데이터를 되돌리는 스크립트 (`scripts/reset_demo.py`). 사용 순서와 확인 명령은 [demo-checklist.md](demo-checklist.md) 참고 | 리허설에서 2회 이상 반복 가능. `python -m scripts.reset_demo --check`가 "합격"을 출력 |

## 1. 시나리오 8단계

| 단계 | 사용자 행동 | 기대 결과 | 검증 대상 | 사용 화면 |
|---|---|---|---|---|
| 1 | 시뮬레이터 시작(정상 모드) | 이미지가 생성되어 1~3초마다 쌓임 | 수집 | 검사/추론 |
| 2 | 자동 판정 확인 | 5초 이내 OK/NG 표시, 정확도 높음(v1) | 추론 | 검사/추론, 대시보드 |
| 3 | 드리프트 주입 | 정확도 하락이 차트에 표시, 성능 저하 경고 | 모니터링 | 검사/추론, 대시보드 |
| 4 | 재학습 실행 | 진행 상태 표시 후 v2 후보 생성 | 학습 | 재학습 |
| 5 | 게이트 평가 | v2가 v1보다 우수하면 승인 요청 자동 생성 | 승격 게이트 | 재학습, 승인 |
| 6 | 관리자 승인 | v2 production, v1 archived | 승인·배포 | 승인 |
| 7 | 추론 결과 확인 | 새 판정부터 model_version=v2, 성능 회복 | 재배포 | 검사/추론, 대시보드 |
| 8 | (옵션) 롤백 | v1 복귀, 이력 기록 | 롤백 | 모델 관리 |

## 2. 단계별 합격 기준

| 단계 | 합격 기준 (측정 가능한 항목) |
|---|---|
| 1 | 시작 후 10초 내 새 검사 3건 이상 생성. 모든 건이 data_split=pool. 이미지가 128×128 흑백 |
| 2 | 모든 판정의 latency_ms ≤ 5000. 판정이 prediction 테이블에 저장. 최근 N건 정확도가 v1의 test_normal 수준과 비슷 |
| 3 | 드리프트 주입 후 최근 N건 정확도(정답 라벨 기반)가 눈에 띄게 하락(3-D 측정, v1 정확도: 정상 환경 1.000 → 드리프트 환경 0.854(시드 42, 3시드 평균 0.987 → 0.809). 이때 재현율은 시드 42에서 1.000, 3시드 평균 0.990으로 거의 유지되고 오경보가 늘어남. data-contract.md C6). 최근 30건 정확도가 0.95 미만이면 대시보드에 경고 표시 (D-3 확정, N=30, T=0.95). 시드 42 측정에서 dark는 경고가 켜지기까지 중앙값 5.5건(2초 간격 11초)이다. 대시보드 폴링 지연은 최대 +5초가 더해진다. noise는 경계 사례라 느릴 수 있고(중앙값 65.5건, 2초 간격 131초), shift는 한계 설명용 |
| 4 | 학습 상태가 대기 → 실행 → 성공으로 전이. 목표 1분 이내(스파이크에서 확인). 실패 시 오류 메시지 표시 |
| 5 | 게이트 조건별 통과/미통과와 실제 수치 표시. 통과 시 stage=staging, approval_request(pending) 자동 생성. 미통과 시 stage=rejected |
| 6 | 운영자 계정으로는 승인 버튼 비활성. 관리자 승인 시 v2=production, v1=archived, deployment·audit_log 기록 |
| 7 | 승인 이후 새 판정의 model_version이 v2. 드리프트 환경에서 v2 성능이 v1보다 높음. 2초 간격 기준으로 dark는 v2 판정이 30건 쌓인 뒤(60초) 경고가 꺼진다. 경고는 최신 30건이 모두 v2 판정이어야 판단하므로 그 전에는 보류이다. shift는 v2로도 회복이 안 될 수 있다(한계 설명용) |
| 8 | 사유 없이 롤백하면 거절. 사유 입력 시 v1=production, v2=archived, 배포 이력에 기록 |

## 3. 예외·실패 시나리오 (자동 테스트 포함)

| # | 상황 | 기대 동작 |
|---|---|---|
| X1 | 게이트 미통과 후보 | rejected 처리, 승인 요청 생성 안 됨, 사유(미통과 조건) 표시 |
| X2 | 새 모델 파일 로딩 실패 | 기존 production 유지, 오류 응답, 감사 로그 기록 |
| X3 | 학습 중 재학습 재요청 | 409 응답, 화면에 "이미 실행 중" 표시 |
| X4 | 이미 처리된 승인 요청 재처리 | 409 응답 |
| X5 | 거절·롤백 시 사유 누락 | 400 응답 |
| X6 | 운영자 계정이 승인·롤백 호출 | 403 응답 |
| X7 | 손상된 이미지 또는 규칙 위반 데이터 | 저장하지 않고 오류 기록 (파트1 품질 체크) |
